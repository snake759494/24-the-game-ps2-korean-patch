# 기술 메모

- 디스크: GAMEDATA 묶음 파일 안에 그룹(`*.group.toc`)별 항목이 있고, 텍스트는 `LTR`(LANG/LNG1 청크, SCSU 인코딩)입니다. 영어·프랑스어·스페인어 LTR이 연속 영역에 있어, 한국어 파일을 그 자리에 쓰고(모자라면 디스크 끝에 추가) 세 언어 항목이 모두 가리키게 합니다.
- 글꼴: `movies_1` 그룹 E2335~2339의 FBM1(PSM0 4bpp 32×32 글리프). fid0은 본문·자막·PDA(전체 한글), fid1은 메뉴 버튼·튜토리얼 패널, fid2는 제목·저장 슬롯·지명 카드. fid3·4는 확인한 화면 어디에도 쓰이지 않아 한글을 넣지 않음(폰트별 표시를 넣은 진단 빌드로 확인).
- 메모리: 글꼴이 레벨 힙에 올라가므로 글리프 수가 많으면 선박 구역 로딩에서 큰 할당이 실패해 멈춥니다(memcpy 대상 0).
- 글리프 공유(v1.3): 게임은 폰트 관리자(전역 0x5fbe70)의 슬롯 배열 {높이, 글리프셋}으로 fid별 글리프를 찾습니다. ELF(SLUS_212.68)를 두 곳 고쳐 fid1·fid2 슬롯이 fid0의 글리프셋을 함께 쓰게 했습니다.
  - 0x4475ac(슬롯 생성 루프): 새 슬롯이 1·2번이면 슬롯 0의 글리프셋을 넣음.
  - 0x447328(폰트 전체 해제 루프): 슬롯 1·2의 글리프셋은 지우지 않음(이중 해제 방지).
  - 추가 코드는 함수 사이 nop 패딩(0x4722c8, 14워드)에 둠. fid1·fid2 파일에는 글리프를 두지 않고, 높이(22·30)는 슬롯별로 그대로 유지.
  - 결과: 게임 시작 지점 레벨 힙 여유 2.21MB → 3.51MB(원본 4.02MB), 최대 연속 여유 1.31MB → 2.65MB.
- 확인 도구: `tools/emu.py`(PCSX2 PINE 메모리 접근·상태 저장), `tools/heap.py`(EE 힙 체인 분석).
